# Clawpatch schema reference (supplementary)

The core wire shape and enum tables are inlined in `SKILL.md`. This file
is supplementary: load it when you need the broader set of internal
record types, provider config matrix, or advanced jq examples.

**Important caveat about this file.** The TypeScript record types below
come from `spec.md` and describe Clawpatch's **internal** model. The
**wire JSON** emitted by `clawpatch report --json`, `status --json`,
etc. uses different field names — for example, on findings the internal
`findingId` field is serialized as `id`, and evidence uses
`path`/`startLine`/`endLine` instead of `file`/`line`. The `--json`
output is also envelope-wrapped (`{ items: [...], findings: <count> }`).

**Treat the TypeScript types below as a sketch, not a contract.** Before
parsing anything, probe the live shape:

```bash
clawpatch report --json --no-color > /tmp/cp.json
jq 'type, keys, (.items // .findings)[0] // empty' /tmp/cp.json | head -40
```

The Clawpatch spec at
https://github.com/openclaw/clawpatch/blob/main/docs/spec.md describes
the internal types. If the live JSON diverges, the live JSON wins.

## All record schemas

### `ProjectRecord` (`.clawpatch/project.json`)

```ts
type ProjectRecord = {
  schemaVersion: 1;
  projectId: string;            // slug from repo remote/root plus stable hash
  name: string;
  rootPath: string;
  git: {
    remoteUrl: string | null;
    defaultBranch: string | null;
    currentBranch: string | null;
    headSha: string | null;
  };
  detected: {
    languages: string[];
    frameworks: string[];
    packageManagers: string[];
    commands: ProjectCommands;  // detected format/lint/typecheck/test cmds
  };
  createdAt: string;
  updatedAt: string;
};
```

Regenerated by `init`. Under this skill's disposable-state model the
whole `.clawpatch/` is gitignored and rebuilt on demand, so this file
is not committed — `init` re-detects it cheaply each session.

### `FeatureRecord` (`.clawpatch/features/<featureId>.json`, often)

```ts
type FeatureRecord = {
  schemaVersion: 1;
  featureId: string;            // slug from kind + entrypoint path/symbol
  title: string;
  summary: string;
  kind: FeatureKind;            // see enum below
  source: FeatureSource;
  confidence: "high" | "medium" | "low";
  entrypoints: FeatureEntrypoint[];
  ownedFiles: FeatureFileRef[];
  contextFiles: FeatureFileRef[];
  tests: FeatureTestRef[];
  tags: string[];
  trustBoundaries: TrustBoundary[];
  status: FeatureStatus;        // see enum below
  lock: FeatureLock | null;
  findingIds: string[];
  patchAttemptIds: string[];
  analysisHistory: AnalysisEntry[];
  createdAt: string;
  updatedAt: string;
};
```

### `FindingRecord` (internal type)

The internal `spec.md` type, reproduced for completeness. **Use the
inlined wire shape in `SKILL.md` for parsing** — the live `--json` output
uses different field names (`id` instead of `findingId`, evidence
`path/startLine/endLine` instead of `file/line`, etc.).

```ts
type FindingRecord = {                  // internal type from spec.md
  schemaVersion: 1;
  findingId: string;            // hash of category + normalized evidence + title; SERIALIZED AS `id`
  featureId: string;
  title: string;
  category: FindingCategory;
  severity: "critical" | "high" | "medium" | "low";
  confidence: "high" | "medium" | "low";
  evidence: EvidenceRef[];      // serialized objects use path/startLine/endLine, not file/line
  reasoning: string;
  reproduction: string | null;
  recommendation: string;
  status: "open" | "false-positive" | "fixed" | "wont-fix" | "uncertain";
  signature: string;
  linkedPatchAttemptIds: string[];
  createdByRunId: string;
  createdAt: string;
  updatedAt: string;
};
```

`report --json` may attach derived fields (`triage`, `nextCommand`, etc.)
that don't appear on the base type. Use whatever the live output gives;
do not hard-code derived field names.

### `PatchAttempt` (`.clawpatch/patches/<patchAttemptId>.json`)

```ts
type PatchAttempt = {
  schemaVersion: 1;
  patchAttemptId: string;       // timestamp + finding-hash prefix
  findingIds: string[];
  featureIds: string[];
  status: "planned" | "applying" | "applied" | "validated" | "failed" | "abandoned";
  plan: string;
  filesChanged: string[];
  commandsRun: CommandResult[];
  testResults: CommandResult[];
  provider: ProviderMetadata | null;
  git: {
    baseSha: string | null;
    commitSha: string | null;
    branchName: string | null;
    prUrl: string | null;
  };
  createdAt: string;
  updatedAt: string;
};
```

### `RunRecord` (`.clawpatch/runs/<runId>.json`)

```ts
type RunRecord = {
  schemaVersion: 1;
  runId: string;                // timestamp + short random suffix
  command: string;
  args: string[];
  rootPath: string;
  headSha: string | null;
  startedAt: string;
  finishedAt: string | null;
  status: "running" | "completed" | "failed" | "cancelled";
  claimedFeatureIds: string[];
  findingIds: string[];
  patchAttemptIds: string[];
  errors: RunError[];
};
```

Useful for resuming with `clawpatch review --resume <runId>` after a
crashed or cancelled run.

## Enum tables

### `FindingCategory` (deslopify mode)

`bug | security | performance | concurrency | api-contract | data-loss |
test-gap | docs-gap | build-release | maintainability`

### `FeatureKind`

`cli-command | route | ui-flow | service | job | agent-tool | library |
config | release | test-suite | infra | unknown`

### `FeatureStatus`

`pending | claimed | reviewed | needs-fix | fixing | fixed | revalidated |
skipped | error`

### `PatchAttempt.status`

`planned | applying | applied | validated | failed | abandoned`

### `RunRecord.status`

`running | completed | failed | cancelled`

### `FindingRecord.status`

`open | false-positive | fixed | wont-fix | uncertain`

## Provider configuration matrix

When `clawpatch doctor` fails or the user wants a non-default provider:

| Provider     | How to select                                  | Notes                                          |
| ------------ | ---------------------------------------------- | ---------------------------------------------- |
| `codex`      | default; or `--provider codex`                  | requires Codex CLI installed and logged in     |
| `acpx`       | `--provider acpx --model <agent>[:<model>]`     | e.g. `claude:sonnet-4-5`, `ollama:llama3:70b`  |
| `grok`       | `--provider grok`                               | requires xAI Grok Build CLI + auth             |
| `opencode`   | `--provider opencode --model opencode/<name>`   | models prefix with `opencode/`                  |
| `pi`         | `--provider pi --model <vendor>/<model>`        | e.g. `anthropic/claude-sonnet-4`               |
| `mock`       | `--provider mock`                               | deterministic, for testing this skill itself  |
| `mock-fail`  | `--provider mock-fail`                          | always fails; for testing failure paths       |

### Provider env vars

| Env var                         | Effect                                          |
| ------------------------------- | ----------------------------------------------- |
| `CLAWPATCH_PROVIDER`            | Default provider name                            |
| `CLAWPATCH_MODEL`               | Default model                                    |
| `CLAWPATCH_REASONING_EFFORT`    | Codex: `low`/`medium`/`high`/`xhigh`             |
| `CLAWPATCH_PROVIDER_TIMEOUT_MS` | Generic per-call timeout                         |
| `CLAWPATCH_ACPX_TIMEOUT_MS`     | ACPX-specific timeout                            |
| `CLAWPATCH_PI_TIMEOUT_MS`       | Pi-specific timeout                              |
| `CLAWPATCH_STATE_DIR`           | Override `.clawpatch/` location                  |
| `OPENCODE_PERMISSION`           | Permission scope for OpenCode                    |

## Config file shape (`.clawpatch/config.json`)

Default after `init`:

```jsonc
{
  "schemaVersion": 1,
  "stateDir": ".clawpatch",
  "include": ["**/*"],
  "exclude": [
    "node_modules/**", "dist/**", "build/**", "target/**",
    ".build/**", ".git/**", ".clawpatch/**"
  ],
  "provider": { "name": "codex", "model": null, "reasoningEffort": null },
  "commands": {
    "typecheck": null,           // auto-detected; user can override
    "lint": null,
    "format": null,
    "test": null
  },
  "review": {
    "maxContextFiles": 24,
    "maxOwnedFiles": 12,
    "maxFindingsPerFeature": 10,
    "minConfidenceToFix": "medium"
  },
  "git": {
    "requireCleanWorktreeForFix": true,
    "commit": false,             // reserved
    "openPr": false              // reserved
  }
}
```

Validation runs commands in this fixed order during `fix`: `format` →
`typecheck` → `lint` → `test`. Any `null` command is skipped.

Bad validator commands are a frequent cause of exit-6 fix failures that
look like the patch is wrong when the issue is the validator itself. If
a fix fails validation and the diff looks plausible, run the validator
commands by hand to see whether the validator is broken.

## Advanced jq recipes

Confirmed against the current wire format (`{ items: [...], findings:
<count> }`). The wire field for a finding's id is `.id` (not `.findingId`),
and evidence uses `.evidence[].path`, `.evidence[].startLine`,
`.evidence[].endLine`.

```bash
# Findings touching a path:
jq '.items[] | select(.evidence[]?.path | test("src/auth/"))' \
   /tmp/clawpatch-findings.json

# Count by category among open findings:
jq '[.items[] | select(.status == "open") | .category]
    | group_by(.) | map({ category: .[0], count: length })' \
   /tmp/clawpatch-findings.json

# Findings linked to a specific patch attempt (post-fix audit):
jq --arg pid "<patchAttemptId>" \
   '.items[] | select(.linkedPatchAttemptIds[]? == $pid)' \
   /tmp/clawpatch-findings.json

# Open findings on features of a particular kind (needs joining with features).
# Note: `status --json` shape is also envelope-wrapped — probe before joining;
# the join key may surface as `id` rather than `featureId` on the feature side.
jq --slurpfile feats <(clawpatch status --json | jq '.features // .items // .') '
  .items[]
  | . as $f
  | $feats[0][] | select((.id // .featureId) == $f.featureId and .kind == "service")
  | { id: $f.id, title: $f.title, severity: $f.severity }
' /tmp/clawpatch-findings.json

# Findings with confidence high AND severity critical only:
jq '[.items[]
     | select(.confidence == "high" and .severity == "critical" and .status == "open")
    ] | length' \
  /tmp/clawpatch-findings.json
```

If the top-level shape of `report --json` is anything other than
`{ items: [...], findings: <count> }`, re-probe with `jq 'type, keys'` and
adjust. The wire format has drifted at least twice — assume it can drift
again across Clawpatch versions.
